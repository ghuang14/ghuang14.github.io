{% comment %} Self-hosted request beacon. Replaces an earlier third-party script, no longer maintained. Sends one pageview to the Cloudflare Worker in edge/, which records geo/network metadata on the server side. Configure in _config.yml under `edge_client:`. If `endpoint` is empty, nothing is emitted at all. Delivery design (see edge/README.md "Why the beacon looks like this"): * fetch(keepalive) is the PRIMARY transport, not navigator.sendBeacon. EasyPrivacy ships an unqualified `*$ping,third-party` rule, and sendBeacon is typed `ping` by every engine, so it is blocked by default in uBlock Origin and Brave. A keepalive fetch is typed `xmlhttprequest` and is allowed by every list tested. * sendBeacon returns true on *queue*, not on delivery, so it can never be treated as proof of success. It is only used as a fallback, always paired with the pixel. * Endpoints are RACED, not chained. The previous version only tried the second host after the first had *proved* itself dead, which is exactly what an unreachable host never does in time: a name that does not resolve, or a black-holed route, hangs until the TCP timeout, the client has navigated away long before that, and no JavaScript is left running to fail over. A working second host was therefore unusable in practice — the one case the fallback existed for. Now host N+1 starts on a timer whether or not host N has answered, and stops early the moment one succeeds. * Every hit carries a random event id and the Worker inserts OR IGNOREs on it, so firing several transports, or several hosts, at once can never double-count. * The address the client reports for itself is looked up from a small set of echo endpoints picked for wide reachability, and sent along. Where this site is read through a mirror or a proxy, the address that reaches Cloudflare is the mirror's; this is the only thing that recovers the client's own. Skipped entirely for DNT/GPC requests. * The send happens at parse time from , on no event at all. `load` waits on the async MathJax script from cdnjs; DOMContentLoaded waits for the whole document, and this used to sit at the bottom of behind a render-blocking bundle. Both meant a client who left early was never counted — an invisible loss, since it looks like less traffic rather than like an error. A preconnect emitted earlier in means the connection is already open when the request is made. * Every pageview reports its own time-to-send, so a regression back to a late send shows up as a number on the dashboard instead of as people quietly going missing. * A pageview that NO endpoint could deliver is kept in localStorage and replayed on a later one. Racing hosts cannot help when every host is on the same name that does not resolve, which is the situation on some networks; the queue is what turns "lost forever" into "arrives when this client is next on a network that works". The event id rides along, so a hit that did get through after all collapses into the row it already made. * The browser's own IANA timezone is sent. It is the only region signal left once traffic exits a VPN or a mirror somewhere else, and the only one a replayed hit carries at all -- by then the connecting address is whatever network finally worked.
